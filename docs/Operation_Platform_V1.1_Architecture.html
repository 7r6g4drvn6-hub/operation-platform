Product position: Operation Platform is not an ITSM, Incident Management, Monitoring, or Probe Management system. It connects evidence to accountable action: Detect → Understand → Act → Prove → Improve.

1. Executive Architecture

V1.1 adds a Signal Intelligence Layer upstream of the existing V1 P0 closed loop. External China-region events are normalized into a common Signal object, correlated into Problem Candidates, and then passed into the existing Problem → Operation → Action → Evidence → Verification → Outcome → History workflow.

External Sources → API / Integration → Source Adapter → Signal Service → Correlation → Problem → Operation → Action → Evidence → Verification → Outcome → China Operation Overview → History

6. Rules and Boundaries

  • Signal is the unified entry object; it is not an Incident and not Evidence.
  • Rule-based correlation uses shared service, region, and time window; no AI is required.
  • A Problem can exist without a Backend Incident. Unreported Problems are first-class attention items.
  • Probe remains an independent product. Operation consumes Probe Results as Evidence.
  • Action completion alone never closes an Operation. Only passed verification can create an Outcome.
  • All Signal → Problem → Operation → Outcome state transitions are recorded in historyEvents.

7. Prototype Scope and Limitations

V1.1 uses Mock Data and a browser-local shared State Layer. The API files define the replacement boundary for future real services while the UI remains decoupled from source-specific payloads.

  • No real Probe, SMO, Incident, Availability, or Release API connections.
  • No production database, Kafka, email parser, AI root cause, predictive detection, or automatic probe trigger.
  • server.js remains unchanged.
